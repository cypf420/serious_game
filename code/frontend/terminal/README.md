# 最小文字终端客户端

本客户端是前端美术与交互方案冻结前的测试入口。它只调用 `code/backend` 的玩家 API，不读取后端源码、内部状态或剧本配置。

当天还有后续剧情时，选择“继续阅读当日剧情”（命令模式输入 `next`）。正文读完后才开放结束当天；`end` 只负责结算和进入次日。

## 启动

先在一个终端启动后端：

```powershell
Set-Location E:\严肃游戏\serious_game_code\code\backend
python -m pip install -r requirements-dev.txt
$env:PYTHONPATH = "src"
python run_server.py
```

再开一个终端运行文字客户端：

```powershell
Set-Location E:\严肃游戏\serious_game_code\code\frontend\terminal
python main.py
```

默认启动后进入编号菜单，普通玩家只需输入菜单前的数字：

```text
【账号入口】
  1. 登录已有账号
  2. 注册新账号
  0. 退出程序
请选择序号：2

【是否观看 NPC 夜间对话】
  1. 不观看（正常游玩）
  2. 观看（观察与调试）
  0. 退出程序
请选择序号：1

【游戏入口】
  1. 开始新游戏
  2. 退出当前账号
  0. 退出程序
请选择序号：1
```

开启观察与调试后，日终会显示每名 NPC 选择联系零人或多人的理由、实际多人转录、模型 ID、动作提案和最终结算，也可从游戏菜单再次查看；普通复盘仍不显示这些私密内容。之后客户端会依次显示决策、NPC、行动、日终、县长案头、地图、知识和复盘菜单。县长案头可随时查阅任务硬约束、五份开局卷宗、补偿政策与财政盘、可调资源、全部行动工具和 36 户公开底表；逐户底表不会显示户群权重、签约锁等隐藏字段，尚缺的地类和附属物数量会明确标为待核验。事实、线索和证据会显示正文、来源及可使用方向。交谈对象菜单会先显示人物姓名、公开身份、简短介绍、前情提要、会谈方向、相关已知材料和行动点消耗；会谈中也可再次查阅这些材料。确认进入时只扣一次行动点，随后可以不限轮次地继续输入自由对话；每轮后都可用编号菜单主动结束，NPC 也可能根据人物底线和上下文送客或离场。与游戏无关的输入会被审查门截断，不计入会谈，也不改变人物状态。未结束的会谈会随存档保存，重启后可继续。普通选择只输入序号；排序题逐项选择优先级；分配题逐项填写额度。只有用户名、隐藏密码、NPC 对话原文和确实需要填写的数值需要键入。与 NPC 交谈会调用当前配置的真实 LLM。

角色生成超过普通 HTTP 等待时间时，客户端会保留本回合唯一的 `client_action_id`，转为查询原操作结果，并明确提示玩家不要重复输入；它不会为同一句话创建第二次模型调用。查询期间后端仍可响应状态和操作接口，结果提交后只按增量 feed 显示一次。若两分钟内仍未完成，客户端会在下一页继续确认同一操作，直到得到成功或失败结果。

首次注册时密码至少 8 个字符；长度不足或两次不一致会说明原因并原地重新输入。后端重启后，菜单会自动检查活动存档并提供“继续活动存档”，不要求玩家输入 `session_id`。

原始命令模式只保留给开发人员检查协议：

```powershell
python main.py --command-mode
```

普通玩家直接运行 `python main.py`，无需记忆 `register`、`new`、`choose`、`talk`、`end` 等命令。

后端和终端进程都会在启动时载入代码。更新本地代码后需要分别停止并重新运行二者；终端会检查 `text-gameplay-v3` 协议版本。若 8100 端口仍是旧后端，会显示 `BACKEND_RESTART_REQUIRED`，避免新终端与旧的会谈或资源动作协议混用。

完整协议见 [M2 终端文字协议](../../backend/docs/03_API与终端/01_M2终端文字协议.md)。
