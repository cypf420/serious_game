# 《浊流之上》全量完善与验收设计

## 目标

把《浊流之上》的质量结论建立在完整 D1–D90、全部发布内容、全部核心机制和真实 AI 玩家体验之上。D1–D20 或单文件测试只允许用于定位问题，不得作为完成或发布证据。

## 当前发布包覆盖基线

当前 `pkg_gameplay_v3` 的硬性基线为：

- 90 个剧情日；
- 24 个主结局；
- 95 个子结局；
- 18 项事实、线索与证据；
- 27 条线索获取路径，其中 11 条查档路径、16 条人物会谈路径；
- 11 份权威档案；
- 32 个人物机会；
- 29 名 NPC；
- 8 个地图地点；
- 6 场剧情定义的夜间强制会谈；
- 36 户搬迁对象；
- 1920×1080、1366×768、390×844 三个视觉验收尺寸。

发布包以后新增任何同类对象时，验收清单必须由内容加载器自动发现并要求补充证据，不能依靠手工记住更新数量。

## 验收层次

### 全量自动测试

每个独立修改批次均执行 Backend、Web、Terminal 全量测试，同时执行 Web 生产构建、Lint、v3 内容哈希、D1–D90 内容矩阵、v2 逐字节一致性、启动器检查和密钥扫描。任一命令失败，当前任务不得进入下一阶段。

单元测试允许使用确定性协议桩验证事务、幂等和异常边界，但这些结果只属于代码回归证据，不能计入真实 AI 体验结论。

### 全量真实 API 验收

真实验收使用公共 HTTPS OpenAI Chat Completions 兼容端点，`ROLE_LLM_FALLBACK_TO_FAKE=false`。服务器默认和个人 API 两种模式均须通过。模型审计中 Fake、模板降级和静默回退均必须为零。

真实验收必须覆盖：

- 完整 D1–D90 路线；
- 所有 24 个主结局；
- 覆盖全部 95 个子结局的合法路线集合；
- 每条声明的线索获取路径；
- 全部档案、人物机会、地图地点与搬迁户；
- 人物会谈、四类治理行动、地图行动、班子会议、合同、文书、保存载入、夜间结算、强制会谈、次晨简报、API 配置和只读复盘；
- API 超时、断流、非法结构、重试、重复点击、旧 worker、状态版本冲突和并发换配置。

如果某个配置对象无法通过合法玩家操作抵达，该对象本身就是内容缺陷，禁止通过直接改数据库或伪造存档将其标记为通过。

### 浏览器体验验收

自动浏览器负责可重复操作、网络记录、控制台、截图和 trace；Codex 内部浏览器用于玩家可见复核。每个主要页面状态必须在三个尺寸下检查无横向溢出、无正文遮挡、等待状态明确、历史对话可回看、按钮有结果反馈、控制台无未归因错误。

## 核心数据流

```text
v3 内容包
  → 内容加载与引用校验
  → 自动生成覆盖清单
  → 合法路线驱动器
  → 后端真实 API 运行
  → Playwright 网页运行
  → 审计、截图、trace、存档与结局证据
  → 覆盖聚合器
  → 全量验收报告
```

覆盖清单使用稳定 ID，不使用标题作为关联键。每个条目至少记录 `coverage_id`、`category`、`source_id`、`required_evidence`、`observed_evidence` 和 `status`。只有证据文件实际存在、审计满足约束且状态为通过时，报告才能计入覆盖。

## 线索与证据规则

每项事实必须至少声明一种可达获取方式。档案路径必须指向真实档案并由该档案授予对应事实；会谈路径必须指向真实人物机会，该机会必须允许或在完成时授予对应事实。开放日前不显示；当日可达路径才进入玩家的“当前可调查方向”。

每条路径分别验证前置不可见、开放后可见、成功获得、重复操作幂等、保存载入恢复、决策联动和未来信息不泄露。拥有两条路径的事实必须分别验证两条路径。

## 结局规则

主结局与子结局都需要合法 D1–D90 见证路线。路线目录只保存玩家可执行的选择、行动和文本策略，不保存最终状态补丁。运行器逐日通过正式 API 推进；结束后核对实际结局，而不是向引擎指定目标结局。

95 个子结局可能互斥，因此允许用多条合法路线完成覆盖。覆盖选择采用集合覆盖聚合，但停止条件固定为主结局 24/24、子结局 95/95，不以路线数量替代覆盖率。

## 失败处理

真实模型技术失败时保持游戏状态不变，并使用同一真实模型按正式重试规则处理；纠错耗尽后记录为失败。不得切换 Fake、模板台词或直接写入预期状态。

发现缺陷后先新增能稳定复现的回归测试，再进行最小修复。修复后先运行全量自动测试，再重新运行受影响的完整 D1–D90 真实路线；最终发布前重新执行全部真实路线集合。

## 工具策略

- `superpowers:executing-plans`：按任务和检查点执行本计划；
- `superpowers:test-driven-development`：缺陷先红后绿；
- `superpowers:systematic-debugging`：定位状态、断流和模型边界问题；
- `superpowers:verification-before-completion`：以新鲜测试证据决定是否完成；
- `superpowers:requesting-code-review`：最终独立审查；
- GitNexus MCP：修改前分析影响范围、修改后检测受影响流程；
- Playwright：可重复浏览器运行、截图、console、network 和 trace；
- Browser MCP：在 Codex 内部浏览器进行玩家可见复核；
- Computer Use：仅用于 Windows 启动器、Word 等非浏览器界面；
- `doc`/`documents`：生成和检查最终报告；
- `imagegen`：仅在确有新背景资产需求时使用。

当前不需要安装 Airtable、Todoist 或交易类插件；它们不能提高本项目的运行正确性。

## 发布门槛

发布必须同时满足：

- Backend、Web、Terminal 全量测试通过；
- Web 构建与 Lint 通过；
- v3 哈希有效，v2 逐字节不变；
- D1–D90 日期和决策顺序完整；
- 24 个主结局和 95 个子结局全部有合法见证；
- 18 项事实的 27 条获取路径全部有成功证据；
- 全部核心功能和三个尺寸完成浏览器验收；
- 真实模型审计 Fake 计数为零；
- API Key 未进入数据库、日志、存档、浏览器存储、截图或报告；
- 验收报告中不存在“未覆盖”或“无证据”的条目。
