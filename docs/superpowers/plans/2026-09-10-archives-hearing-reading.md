# 档案引用、听证事实与剧情阅读 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 在不改变既有合同、经济和结局规则的前提下，完成用户确认的档案统一查看、对话 @ 引用、听证事实同步、阅读结束门槛及限定界面优化。

**Architecture:** 沿用现有档案、会议、公文和会话存储；新增只读统一投影及可选引用字段，不复制文件或变更存档结构。听证进度从真实行动和会议记录推导，NPC上下文使用权威结果，引用本身不产生办理效果。

**Tech Stack:** Python / FastAPI / pytest，React / TypeScript / Node tests / Playwright。

**Spec:** 本任务对话中用户确认的六项优化方案、@ 文件引用、档案统一入口及“不要擅自改动不在优化范围内的功能，不要影响正常功能的使用”。

## Global Constraints

- 不调整经济数值、人物设定、剧情选择、结局判定、账户或存档管理。
- 合同仅沿用既有会议红头文件应用规则，不允许档案引用绕过合同校验。
- 没有引用的对话保持兼容；不新增模型供应商、依赖或后台服务。
- 不执行提交、推送、部署；不操作用户存档；测试使用隔离会话。
- 修改已有符号前调用 GitNexus impact；索引未知时报告不确定性并人工检查调用方。
- 叙事与界面数字格式分层统一，不转换户号、文件编号、合同正文或金额。

## Ownership and execution

- backend: `code/backend/` 的引用API、真实文件解析、NPC上下文、听证进度及测试。
- frontend: `GameShell.tsx`、`app/lib/api.ts`、CSS、新档案与引用组件、交互测试。
- narrative: `app/lib/narrative-model.ts`、`scene-resolver.ts`、`player-ui.ts` 及对应测试；剧情数据修改须与backend协调。
- root: 本计划、教程文案、跨模块审查及回归报告。
