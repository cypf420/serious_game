# 《浊流之上》作为完整游戏的系统评价与优化建议

日期：2026-09-07<br>
评估对象：`serious_game_code`，分支 `codex/serious-game-v3-implementation`，提交 `94651b9`<br>
评估视角：完整游戏体验、可玩性、系统因果、严肃游戏学习价值，而不仅是代码功能是否存在。

## 1. 结论先行

《浊流之上》已经具备一个严肃游戏原型所少见的工程基础：90 日时钟、行动点和预算、NPC 状态、合同与材料、夜间模拟、结局轴、存档快照、审计日志，以及真实模型和规则结算的边界。GitNexus 已同步索引到当前提交：448 个文件、13,471 个节点、26,645 条边、306 个社区、300 条流程；后端的 `ActionService`、`EndDayService`、`NightSimulationService`、`EndingService` 等也已经形成相对完整的应用层骨架。

但是，按照成熟游戏评价体系衡量，项目目前更准确的定位是：

> 一个技术上内容丰富、可审计、可继续打磨的严肃游戏系统，而不是已经完成玩家体验闭环的完整游戏。

最关键的问题不是“功能还不够多”，而是以下因果链还没有在所有主要玩法中稳定成立：

```text
玩家发现具体矛盾
    → 获取并核实材料
    → 与相关人协商
    → 选择可承担的处理方案
    → 办理、签约或交办
    → 在未来日期得到可解释的反馈
    → 面对新的约束并复盘
```

项目的内部规则、剧情文本、AI 会谈、合同资源和结局系统已经分别存在，但玩家并不总能判断“一句话改变了什么”“下一步应该去哪里落实”“事情何时才算完成”。这会直接损害玩家的控制感、反馈感、挑战公平性、沉浸感，也会削弱严肃游戏最重要的学习迁移价值。

因此，下一阶段不建议继续优先增加新的工具、人物或结局数量，而应优先完成一个可反复验证的“事项闭环”，再把这套闭环扩展到全游戏。

## 3. 采用的成熟评价体系

本报告不把“好不好玩”简化为主观印象，而使用互补的五组标准。

### 3.1 MDA：机制—动态—体验

MDA 将游戏拆成 Mechanics、Dynamics、Aesthetics：设计者定义规则和素材，玩家通过行动产生动态过程，最终形成挑战、发现、叙事、沉浸等体验。它适合检查本项目是否存在“机制各自成立，但动态结果没有汇合”的问题。

参考： [Hunicke、LeBlanc、Zubek，MDA: A Formal Approach to Game Design and Game Research](https://www.cs.northwestern.edu/~hunicke/MDA.pdf)。

### 3.2 GameFlow：玩家是否进入可持续的游玩状态

GameFlow 从专注、挑战、技能、控制、清晰目标、反馈、沉浸、社会互动八个方面评价享受感。对于本项目，重点不是追求动作游戏式刺激，而是让玩家知道目标、理解规则、感到选择有效，并愿意继续调查下一件事。

参考： [Sweetser、Wyeth，GameFlow: A Model for Evaluating Player Enjoyment in Games](https://www.valuesatplay.org/wp-content/uploads/2007/09/sweetser.pdf)。

### 3.3 HEP：可玩性启发式

Desurvire 等人的 Playability Heuristics 将评价范围扩展到 gameplay、story、mechanics 和 usability，而不只检查按钮是否能点击。本报告用它检查流程是否冗余、行动是否有意义、叙事和机制是否互相支持。

参考： [Desurvire、Caplan、Toth，Using Heuristics to Evaluate the Playability of Games](https://www.valuesatplay.org/wp-content/uploads/2007/09/desurvireplayabilityheurist.pdf)。

### 3.4 EGameFlow：严肃游戏的游玩与学习体验

EGameFlow 在 GameFlow 基础上加入知识改进，并关注专注、挑战、自主、沉浸、社会互动和学习结果。它提醒我们：严肃游戏不能只证明“玩家完成了任务”，还要证明玩家获得了可辨识、可迁移的理解。

参考： [Fu、Su、Yu，EGameFlow: A Scale to Measure Learners' Enjoyment of E-learning Games](https://doi.org/10.1016/j.compedu.2008.07.004)。

### 3.5 严肃游戏 UX 与游戏—教学机制一致性

严肃游戏的 UX 评价需要同时考虑 gaming experience、learning experience、adaptivity 和 usability，而不是只测界面易用性。游戏机制还必须和学习目标对应：机制产生的选择、反馈和后果应当正好练习目标能力，而不是让玩家先玩一套游戏、再额外阅读一套说明。

参考： [Moizer 等，An approach to evaluating the user experience of serious games](https://doi.org/10.1016/j.compedu.2019.04.006)； [Introducing the Serious Games Mechanics](https://doi.org/10.1016/j.procs.2012.10.091)。

## 5. 主要问题与优化建议

### P0-1：核心因果链没有覆盖所有行动

**对应标准：** MDA 的 Mechanics→Dynamics，GameFlow 的 Control、Clear Goals、Feedback，HEP 的 Gameplay/Mechanics。

**证据：** 当前行动层已经支持报价、行动点、预算、事实和幂等；但优化记录明确写着“部分工具仍缺内容专属后果及后续入口”。31 项工具中只有 26 项启用，5 项资源动作因正式数字或稀缺资源台账缺失而禁用。机制批判文档也明确指出固定日程、AI 会谈、合同资源和文件办理经常各自有功能，却没有让玩家看到它们之间的同一条事实链。

**玩家后果：** 玩家会把游戏理解成“阅读剧情—猜会谈回答—填写流程—等待结局”，而不是“处理一件具体公共事务”。当行动只记录日志、消耗点数或轻微改变指标，却没有改变后续机会、NPC 立场、资源约束或事件状态时，这个行动对玩家来说就是装饰性操作。

**建议：** 给每个玩家可见行动建立统一的“行动契约”，至少包含：

```text
当前事项 / 公开目标 / 前置事实 / 成本 / 可获得信息
成功后改变什么 / 失败或拒绝后发生什么 / 下一次反馈日期 / 可追溯证据
```

技术日志可以继续保留完整字段，但玩家界面只需要显示能帮助决策的内容。凡是不能改变玩家选择、资源约束、角色行为、未来结果，且不承担必要理解作用的操作，应从玩家界面合并或删除。

**验收：** 对所有公开行动逐项抽查，100% 能回答“我为什么现在做、做完后改变什么、何时能看到结果”；代表性路线中不再出现“行动完成但没有下一步”的孤立节点。

### P0-2：隐藏状态保护了神秘感，也隐藏了太多因果

**对应标准：** GameFlow 的 Feedback、Clear Goals、Control；EGameFlow 的 Autonomy、Knowledge Improvement；HEP 的 Usability。

**证据：** 项目有意隐藏政治信用、关系变化、NPC 底线和部分结局轴，这对角色扮演有价值；但多周目报告显示，玩家在 D75 明确选择“复检、治疗、费用逐项落实”后，仍然得到“揭而未治”，导致 `ending_07`、`ending_22`、`ending_23` 自然不可达。另有 `ending_24` 被前置结局条件完全遮蔽。这里的问题不是玩家看不到内部数字，而是玩家看不到“需要补足的公共事实”和“自己的选择为什么没有产生预期结果”。

**建议：** 采用“隐藏数值、公开因果”的原则：

- 不显示所有内部加减分，但显示事项状态、已确认事实、尚缺材料、责任人和下一次可验证日期。
- 失败时说明缺的是事实、权限、资源、时间还是关系，而不直接揭示完整隐藏条件。
- 结局卡增加“证据链”：至少列出 3 条导致该结局的事项事实，以及 1 条本可改变结果的分歧点。
- 对重要治疗、交房、签署、复检等动作，建立明确的状态迁移；不能让“玩家选择过某个语义相近选项”代替正式事实记录。

**验收：** 新玩家不看攻略也能在每个关键事项上回答“当前冲突是什么、谁能推进、还缺什么、下一次反馈何时发生”；所有已发布主结局都有合法路径，所有高优先级选择都能在复盘中指向具体事实。

### P0-3：90 日规模和当前节奏可能把治理决策稀释成日历操作

**对应标准：** GameFlow 的 Concentration、Challenge、Clear Goals；HEP 的 Gameplay；认知负荷与严肃游戏 UX。

**证据：** 当前内容包是 90 日、每日 8 行动点；项目曾提出 45–55 分钟单局、18–24 个关键行动日和可快进日的设计目标，但当前优化状态又保留了 D1–D89 每日开放行动、89 次夜间转换。31 局实验虽然能完成 D1→D90，却不能证明每一天都提供了等价的、有意义的决策。

**玩家后果：** 关键冲突、行政手续、关系变化和普通等待被放在同一时间粒度，玩家会疲于处理“今天还能点什么”，而不是集中注意力判断“现在最重要的公共风险是什么”。日历越长，任何一天的行动后果越难被记住，学习也越容易变成记忆事件顺序。

**建议：** 采用“关键日 + 可解释快进”的双层时间结构：

- 每章明确 3–5 个关键日；关键日承载冲突升级、证据确认、谈判和承诺。
- 非关键日可以批量快进，但必须让玩家选择“等待、交办、核查、加班”中的策略，并显示快进期间可能错过的窗口。
- 每次快进生成“发生了什么、为什么发生、哪些事项进入下一阶段”的公开晨报。
- 保留 90 日作为治理期限，但不要求玩家把 90 次日终都当作同等重量的玩法回合。

**验收：** 通过真人试玩测量单局时长、每个关键日停留时间、无意义点击数和玩家对当前目标的回忆率；关键日占主要决策时间，空档日不会迫使玩家重复寻找没有后果的操作。

### P0-4：社会互动引擎很丰富，但自然路径下没有形成可见的游戏体验

**对应标准：** MDA 的 Dynamics/Aesthetics；GameFlow 的 Immersion、Social Interaction；EGameFlow 的 Social Interaction。

**证据：** 后端已有 `NightSimulationService`、群组会话、follow-up、关系和 NPC 状态等完整结构；但 31 局完整自然路径实验中，玩家可见的逐轮夜间 Agent、强制群组或 follow-up 对话均为 0 场。项目同时记录了 NPC 知识边界、关系传播、谎言和部分隐藏信息仍未完全冻结。

**判断：** 代码中的社会模拟规模不等于玩家感受到社会互动。夜间系统如果只在内部更新状态，或者只生成玩家无法追溯的简报，就会成为“研究数据引擎”，而不是游戏动态。反过来，如果强制玩家逐轮处理无后果对话，也会增加负担，因此目标不是把所有内部互动都展示出来，而是让重要互动以可选、可核实、有后果的方式进入主循环。

**建议：**

- 每章至少安排一个可自然触发的社会变化：有人改变立场、带来材料、传播未经证实的消息，或使某个窗口提前关闭。
- 夜间交互只有在改变后续选择、信息可信度、资源约束或 NPC 行为时才展示；其余保留为内部模拟。
- 晨报显示“可核实事实”和“待核消息”，不让玩家全知式看到所有私谈。
- 为每个主要 NPC 规定：可知信息、愿意透露的信息、会误解的信息、可执行承诺、下一次反馈窗口。

**验收：** 在代表性的低压、公开、调查、强硬路线中，玩家都能看到至少一次社会状态变化，并能通过合法行动验证或修正它；夜间可见内容不再长期为零，也不以无后果对话填充时长。

### P0-5：行政流程正在压过游戏中的“决策动词”

**对应标准：** HEP 的 Gameplay/Usability；GameFlow 的 Control；MDA 的 Mechanics。

**证据：** 31 项工具、合同、文件、会议、材料和审校流程体现了治理真实性，但机制批判文档已经指出“填无关表单”的风险，并建议删除独立资源承诺操作，将资源扣除放在正式签约时完成。当前技术实现中，不同工具的入口、报价、资源和事实状态仍需要玩家自己拼接。

**建议：** 把玩家可见的主要动作收敛为 6–8 个决策动词：

```text
发现 / 核实 / 约谈 / 协商 / 决定 / 承诺或签署 / 跟进 / 复盘
```

合同、审批、材料归档和审计字段保留在系统内部或作为一个复合动作的结果。玩家仍然可以感受到制度约束，但不需要为同一件事分别操作“登记、预占、承诺、确认交付、登记违约”等重复按钮。

**验收：** 完成一个完整事项所需的玩家主动操作数量明显下降；每个复合动作都能在一个事项卡中看到条件、代价和后果；技术审计字段不再要求玩家重复确认同一事实。

### P1-1：资源与指标有规模，但未必都构成真正的取舍

**对应标准：** MDA 的 Dynamics；GameFlow 的 Challenge/Control；HEP 的 Mechanics。

**证据：** 当前有预算、签约户数、公共信任、社会稳定、政治信用、舆情压力、廉政、干部不满、疲惫等状态。数量多本身不是深度；如果某个指标不限制行动、不改变 NPC、不给出未来风险或不影响结局证据，它就只是界面噪声。机制批判文档还指出，部分顶部指标没有清晰行动反馈，政治信用的行动限制函数存在无阻塞情形。

**建议：** 对每个常驻指标做“决策用途审计”：

| 问题 | 若答案为“否” |
|---|---|
| 玩家能否通过可理解的行动改变它？ | 不应常驻显示。 |
| 它是否改变未来机会、NPC 行为或资源约束？ | 合并为事项状态或后台记录。 |
| 玩家能否在结果出现时追溯变化来源？ | 增加事项化反馈。 |
| 它是否对应明确的学习目标？ | 不要为保留复杂度而保留。 |

### P1-2：自由文本与硬结算的边界需要更像“可学习的谈判”，而不是“猜模型喜欢什么话”

**对应标准：** GameFlow 的 Challenge/Control；EGameFlow 的 Autonomy/Knowledge Improvement；严肃游戏机制—教学一致性。

**证据：** 项目已经正确地把 LLM 定位为角色判断，把预算、合同、硬事实和结局交给规则层；这是工程上的优点。但如果玩家只能通过反复试探自然语言来猜 NPC 的接受方式，而游戏又不公开当前议题、谈判空间和可验证标准，那么自由文本会变成不透明的提示词竞赛。

**建议：** 每次会谈都明确一个“当前议题”和一个“可推进的事实”，允许玩家自由表达，但在反馈中说明：

- NPC 听懂了什么；
- 哪一部分被接受、拒绝或保留；
- 下一步需要什么证据、资源或第三方；
- 是否形成可执行承诺，还是只有口头态度。

这样既保留自然语言和人格差异，也让玩家学习治理方法，而不是学习某个模型的偏好。

### P1-3：结局数量不能替代可达性和分支意义

**对应标准：** MDA 的 Dynamics；GameFlow 的 Replayability/Feedback；严肃游戏的反思与迁移。

**证据：** 当前规则资产有 24 个主结局和 95 个亚结局，但多周目实证为 20/24 个主结局自然可达，4 个不可达；未采样的 75 个亚结局不能直接等同于不可达，但说明“内容数量”与“玩家可体验分支”之间仍有距离。`ending_24` 还被表序结构性覆盖，三个含“已治”状态的结局被缺少状态 setter 阻断。

**建议：** 建立版本化的“结局可达性矩阵”，每个已发布结局必须有：

- 至少一条从新存档开始的合法路径；
- 关键状态的唯一或明确 setter；
- 与其他结局不同的玩家决策链；
- 结局被前置条件遮蔽时的设计意图；
- 结局正文中可指向的事项证据。

如果某个结局只是资产占位或研究实验，不应在玩家可见的“结局总量”中宣传为已完成内容。

### P1-4：严肃游戏的学习目标和迁移验证还不够明确

**对应标准：** EGameFlow、严肃游戏 UX、多维学习效果评价。

**证据：** 项目已经记录了行动日志、对话日志、夜间日志、承诺和结局日志，研究价值很强；但现有验收更集中在 D1→D90 能否跑通、JSON 是否有效、结局是否命中、日志是否存在，尚缺少“玩家到底应学会什么、如何观测、如何迁移”的明确映射。

**建议：** 先冻结 5–8 个可测学习目标，例如：

1. 能区分传闻、已核实事实和制度性证据。
2. 能识别不同利益相关者的诉求、权限和底线。
3. 能在预算、时间和公平性冲突下说明方案取舍。
4. 能区分口头态度、正式承诺、资源分配和实际交付。
5. 能判断何时应继续协商，何时应核查、升级或暂停。
6. 能根据后续反馈修正原先的判断，而不是只追求一次对话成功。

每个目标都应绑定：游戏机制、玩家可观察行为、即时反馈、结局中的证据、局后反思题和一个新的迁移情境。否则玩家可能学会“通关这套脚本”，而不是学会治理中的判断方法。

### P2-1：可用性修复很多，但还没有形成系统的人因验收

已有报告记录了响应式布局、结局卡、错误处理和横向溢出等修复，这是正面基础。但严肃游戏的可用性还应覆盖键盘操作、焦点顺序、信息密度、术语理解、低带宽/模型失败后的恢复、长局疲劳和首次玩家是否能找到下一步。建议在技术回归之外增加任务型试玩：不看攻略完成“发现材料—约谈—签约—等待反馈”四步，并记录误操作、回看次数、放弃点和目标复述准确率。

### P2-2：规格和运行口径需要单一事实源

当前产品需求中曾出现“每日 3 行动点”，而 `pkg_gameplay_v3/numbers.json` 当前为每日 8 行动点；设计优化文档和内容包也存在“工程已接通”和“内容仍为 draft”的不同口径。这不一定是运行时 bug，但会让设计、测试和研究报告对同一局游戏使用不同假设。

建议建立单一版本事实表，至少锁定：天数、每日行动点、预算单位、关键日、工具启用状态、结局可达状态、学习目标版本。任何文档的数字变更都必须由内容包验证器和回放验收共同确认。

## 6. 建议的目标版核心循环

### 6.1 玩家真正应该反复执行的循环

```text
看见一个具体公共问题
    ↓
提出当前假设：谁受影响、事实是什么、最紧迫风险是什么
    ↓
核实材料或寻找知情人
    ↓
与利益相关者协商，获得可执行信息
    ↓
选择可承担的方案：资源、权限、公平性、时间相互取舍
    ↓
办理、签署、交办或暂缓，并留下可审计事实
    ↓
在约定日期获得交付、拒绝、延误或新的风险反馈
    ↓
修正方案，进入下一件相互关联的事项
```

剧情阅读、文件、夜间模拟、合同、结局和研究日志都应该服务于这条循环。任何系统若无法说明自己在循环中的位置，就需要合并、隐藏或删除。

### 6.2 一个事项的最小可交付标准

以“住房/医疗/迁坟/就业”等事项为单位，而不是以单个按钮为单位，建立如下验收卡：

| 阶段 | 玩家必须知道的内容 |
|---|---|
| 发现 | 发生了什么，谁受到影响，为什么现在重要。 |
| 核实 | 哪些是事实、传闻、缺失材料或相互矛盾的说法。 |
| 协商 | 当前议题是什么，谁能决定，哪些方案可谈。 |
| 决定 | 每个方案的预算、时间、公平性和失败代价。 |
| 执行 | 什么被正式记录，什么仍只是口头态度。 |
| 反馈 | 何时、通过谁、以什么证据确认结果。 |
| 复盘 | 哪个选择造成了结果，下一次可以怎样改变。 |

### 6.3 先做一条纵向切片

不要先全面重写 90 日。建议选择一个能同时覆盖会谈、证据、预算、合同、交付和结局的代表事项，做一条从 D1 到结局的纵向切片。该切片需要满足：

- 玩家可以从公开材料发现问题；
- 至少一次信息核实会改变可用方案；
- NPC 会明确接受、拒绝或保留某个具体部分；
- 合同/资源只在真实承诺时扣除；
- 后续日或夜间产生可核实反馈；
- 结局卡能列出事项证据链；
- 同一事项在剧情、会谈、案头、合同和结局中保持一致。

纵向切片通过后，再将规则推广到其他住户、干部和事件。这样能避免继续扩大内容资产，却把同一类因果断点复制到全包。

## 7. 分阶段优化路线

### 阶段一：冻结游戏真相表（最高优先级）

1. 冻结 `numbers.json`、每日行动点、关键日、预算单位和指标用途。
2. 为 31 项工具建立启用/禁用/研究占位的明确标签；5 项禁用动作要么补齐正式数字并上线，要么从玩家可见主流程移除。
3. 生成 24 个主结局的可达性矩阵，修复三个“治疗状态”缺 setter 的问题，并决定 `ending_24` 是真正可达还是删除占位。
4. 为主要事项补齐事实、承诺、交付、失败、反馈日期和证据来源。

### 阶段二：完成一个完整事项纵向切片

用上文的“发现—核实—协商—方案—执行—反馈—复盘”验收一个代表事项。阶段二不以增加新工具数量为目标，而以玩家能否独立解释当前冲突和下一步为目标。

### 阶段三：重排时间与社会系统

将 90 日改造成关键日和快进日的组合；让夜间模拟只展示会改变选择的互动；在至少三条代表路线中验证低压、调查和强硬策略是否都能触发可理解的社会反馈。

### 阶段四：把学习目标接入游戏与复盘

冻结 5–8 个学习目标，为每个目标添加可观测行为、反馈、结局证据和迁移题。区分“通关表现”“决策质量”“局后解释质量”，不要只用签约户数或结局名称代表学习效果。

### 阶段五：真人试玩和回归验收

至少分两轮：第一轮发现流程和理解问题，第二轮测量目标、时长、错误、反馈和学习迁移。保留现有自动化回放、规则测试、真实模型 smoke test 和日志审计作为底座，但不能用它们替代玩家研究。

## 8. 建议纳入 CI/试玩的验收指标

| 指标 | 目标 |
|---|---|
| 行动因果闭环率 | 100% 的玩家可见关键行动都有公开目标、成本、后果和下一次反馈。 |
| 主结局合法可达率 | 所有对外发布的主结局 100% 有新存档合法路径；占位结局不计入宣传数量。 |
| 事项一致性 | 同一事项在剧情、会谈、案头、合同、日志和结局中的事实一致率 100%。 |
| 空转操作率 | 试玩中不改变选择、资源、角色行为或理解的主动操作降到最低，并逐项有删除或保留理由。 |
| 关键日密度 | 45–55 分钟目标单局中，主要决策集中在 18–24 个关键日或等价的关键节点。 |
| 社会反馈可见性 | 每条代表路线至少产生可核实的社会状态变化；夜间系统不再长期出现可见互动为零。 |
| 结局证据链 | 每个结局至少能指向 3 条事项事实和 1 个可改变分歧点。 |
| 学习目标覆盖 | 每个学习目标至少绑定 1 个机制、1 个可观察行为、1 条反馈和 1 个迁移问题。 |
| 工程可靠性 | 保留现有规则优先、幂等、快照恢复、模型失败不损坏状态、真实模型与 Fake LLM 分离的约束。 |

## 9. 最终判断

项目最值得保留的不是“90 日、31 工具、24/95 结局”这些数量本身，而是它已经具备把复杂治理过程做成可审计模拟的能力。下一步的关键，是把这种后台复杂度转化成玩家能理解、能选择、能验证、能复盘的前台因果。

如果继续优先扩展资产数量，项目可能得到一个“内容更多但更难解释”的系统；如果先完成事项闭环、时间重排、社会反馈可见性、结局可达性和学习目标映射，现有工程基础才会真正转化为完整游戏品质。

因此，本项目当前最准确的优化目标不是“再做更多玩法”，而是：

> 让玩家在每个关键时刻都清楚自己正在处理哪件事、依据是什么、承担什么代价、改变了谁，以及结果将在何时以什么证据回来。

这条标准同时满足 MDA 的动态一致性、GameFlow 的控制与反馈、HEP 的可玩性、EGameFlow 的知识改进要求，也最符合《浊流之上》作为严肃治理游戏的独特价值。
