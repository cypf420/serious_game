# 赴任指南：内容、接入与验证

## 设计与范围

采用“聚光灯高亮＋情境讲解＋自主操作”。开局八步导览介绍界面，其中“主动推进签约”高亮状态栏的签约入口，解释筛选住户或代表、会谈、合同与实际签署的关系；行动按具体办理方式独立介绍；首次核对行动安排时讲解原有表单。教程不请求业务写入、不消耗精力、不替玩家作出选择。

教程入口为顶部“赴任指南”、前三日上手卡、行动卡的“了解此行动”和表单内“填写指南”。新存档先邀请，玩家可以稍后再看。场景帮助先显示简短邀请；表单在数据准备完成后自动讲解。自动提示可在目录关闭。

参考：
- [NN/g 情境帮助与渐进呈现](https://www.nngroup.com/articles/onboarding-tutorials/)
- [Game Accessibility Guidelines 交互式教程](https://gameaccessibilityguidelines.com/include-interactive-tutorials/)

## 代码职责

前端 `app/tutorial/` 中：

- `types.ts`：教程、步骤、上下文及进度类型。
- `definitions.ts`：基础导览、九项办理方式、表单与场景教程的中文文案。`ACTION_COPY` 按 `variant_id` 配置。
- `progress.ts`：存储校验、账号隔离、章节修订与存储异常回退。
- `TutorialProvider.tsx`：目录、邀请、暂停恢复、场景匹配与公开行动描述缓存。
- `TutorialOverlay.tsx`：Portal 遮罩、滚动定位、键盘约束、字段校验和焦点恢复。
- `tutorial.css`：专用样式。弹层使用 `tutorial-popover`，不得复用已有静态上手卡的 `tutorial-card` 类。

`GameShell.tsx` 传入公开上下文，提供 `data-tutorial-id` 定位标记。修改后端业务流程时，不得让教程模块直接导入或实例化 `GameApi`。

`app/lib/action-presentation.ts` 按具体 `variant_id` 提供行动表单、发言、结束与记录文案。`leadership_meeting` 是共用业务协议，不代表所有变体都采用班子会议文案：公开听证与宗族议事使用各自议题、参与人和结论，不显示牵头领导或拟制行政文件字段。结果通过 `action_instance_id` 关联原行动；普通记录使用阅读指南，行政文件才显示文件操作指南。宗族议事复用现有祠堂场景素材。

## 修改或增加章节

1. 使用稳定业务标识关联教程。不得按中文按钮文本、数组序号或绝对屏幕坐标定位。
2. 行动章节只能从当前后端公开的 `actions/variants` 描述生成。静态文案字典不代表玩家已解锁内容。
3. 消耗调用 `actionPointLabel`，人数与有效性读取原表单状态。不要在教程中写死精力、人数和剧情解锁日。
4. 标题不超过 12 个汉字，主要说明原则上不超过 90 个汉字；用途、适用时机、操作、成本与结果的长说明放入 `detail`。
5. 条件字段设为 `optional`。只有到达该步骤时才判断字段是否存在，例如参会人选定后出现的牵头人、拟形成文件后出现的证据选择。
6. 可填写字段设 `interactive: true`，相应容器的 `data-tutorial-valid` 绑定真实表单校验。实际业务提交按钮只能作为非交互讲解目标。
7. 最后一步使用“讲解完成，自主操作”，退出后焦点交还原提交按钮。真实提交是否成功只由原业务结果决定。
8. 修改章节含义或步骤顺序时增加该章 `revision`。不要通过清空所有浏览器存储重置教程。

## 状态边界

- 账号标识来自现有客户端账号 ID；本地试玩使用现有稳定试玩身份。
- 浏览器键为 `qingjiang:tutorial:v1:<encoded account ID>`；不存对话、表单内容、令牌或游戏存档。
- 开始新游戏或切换游戏进度时递增教程代次，清除当前高亮与本次存档已见的行动描述，防止旧节点看到未来行动。
- 已学章节在同账号下保留；自动提示偏好同样按账号隔离。不同设备不共享进度。
- 存储被禁用、超额或损坏时回退到内存；游戏可以继续。教程状态不属于正式游戏状态。
- 登录、授权、存档选择、业务确认、督办与 AI 等待期间暂停教程。
- 文书、合同和查档结果弹窗只允许匹配弹窗本身的教程；基础导览不应高亮被弹窗覆盖的页面。
- 缺失必需目标时显示无整页遮罩的暂停提示，可重试或关闭，不能自动标记完成。
- 小屏教程临时为滚动容器预留卡片高度；退出和切换步骤时恢复原样。不要把这部分留白写入业务表单的固定样式。
- 只读复盘不显示可执行行动教程。返回对应场景后可从目录重播已公开章节。

## 验证方法

在 `code/frontend/web` 执行：

```powershell
node --test tests/tutorial-model.test.mjs
node --test tests/action-semantics.test.mjs
npx playwright test --config playwright.component.config.ts e2e/tutorial.spec.ts
npx playwright test --config playwright.component.config.ts e2e/action-semantics.spec.ts
npm run check
```

浏览器组件测试使用固定接口样例及独立试玩身份。涵盖无业务写入、动态字段、成本、失败保留表单、成功结果、刷新续看、首次表单提示去重、行动介绍去重及新增公开行动、人物介绍嵌套弹窗、只读及公开内容边界。响应式截图检查 1920×1080、1366×768、390×844，实际点击小屏人物选项，避免仅凭静态卡片截图判断可操作性。

本地后端验证使用 `environment=test`、内存仓库及 `fake` 角色模型，只操作测试存档，验证真实后端的查档扣费与事实入库、会谈结束归档。此验证不代表外部模型服务或线上部署验收。

实现期间 GitNexus 的数据库在中文根路径打开失败，使用当前源码的 ASCII 路径副本恢复影响分析。页面与表单接入为 LOW；通用 `perform` 被标为 CRITICAL，因此保持该函数不变，结果提示只接在具体操作成功分支。

## 合同阶段帮助（2026-09-09）

合同定义位于 `app/tutorial/contract.ts`，分为 terms、preview、feedback、signed、legacy 五个独立修订章节，正文直接展示，无展开说明。ContractWorkspace 按真实编辑状态上报阶段和合同 ID；切换住户或阶段时原教程暂停，不复用其他住户的目标。教程没有保存、提交或模拟签署能力。

填写阶段只讲字段用途；反馈阶段只讲阅读顾虑和继续协商，不显示本户答案或全部条件。无住房时交房日隐藏且请求省略，有住房仍要求有效日期。基础导览前两张保持原样。
