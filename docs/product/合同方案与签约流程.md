# 合同方案与签约流程

本说明对应2026年9月9日确认的合同设计。

## 玩家操作

在相关签约人或代表的入户会谈中办理逐户合同：填写方案 → 保存方案并预览合同 → 提交签约。合同正文为只读，玩家修改基础补偿、住房、服务和批准依据；系统自动安排日期、过渡月份与预算分项。系统保存时自动核验政策与资源，不再调用合同生成模型和专业审校模型。自动安排的计算口径见《合同方案自动安排》。

提交后满足本户实际条件即签署，合同立即生效，并支付款项、分配住房及服务名额。合同记录交房、搬离及服务安排；这不表示另有交房或治疗操作入口。拒绝或继续协商不扣资源，各户独立签署。

合同只保留实际需要玩家决定的方案内容。只有一份有效补偿方案时展示文件名称和原文，不再提供单选下拉框，也不把这份依据重复列入补充批文。原“公开签约奖励”取消独立勾选和独立条款；现有政策中的限期奖励由后端按日期判断并纳入政策标准，包含在现金总额内，不另行加付。旧客户端和已保存方案的显式奖励标记暂作兼容，已签合同不改写。

新草案的基础补偿默认值取后端按本户人口和面积计算的政策标准，不再统一填100万元。系统根据所选房源的等待时间计算过渡补偿，保存后在合同中列明基础补偿、过渡补偿和总额。浏览器输入校验和接口失败信息都在合同窗口内展示；未保存成功时保留输入，保存期间明确显示处理状态。

对方要求解释时，点击“继续协商”返回既有入户会谈。会谈会带入本人或代表所属批次的当前合同及答复，代表的转述不代表其他住户已经同意。方案或实际事项变化后可重新提交，无需手改正文。人物自由答复不新增签约门槛；未满足时只表达一项顾虑，不给出全部解法。重复提交不重复扣款。

## 版本与旧合同

原样保存方案不增加版本、不清空反馈。改变方案后生成新版本，旧答复收进带版本的协商记录。未保存修改不能提交签约，离开页面或切换家庭前提示保留或放弃。

已签署合同保留原始正文和签署账务。旧未签署草案必须核对特殊约定，再明确确认按当前方案生成；历史原文持续保留，不把自由文本自动转成实际资源。

## 实现边界

- 标准正文由 `application/contract_workflow.py` 生成，内部资源键只用于查找与账务。
- `terms` 接口校验后保存；可用资源不足时返回对应选项的自然语言提示。
- `text` 接口保留为拒绝修改的兼容入口，旧客户端不能再通过正文增加承诺。
- `review` 接口检查当前方案版本、资源及会谈，依据相关输入指纹防止无变化重试；指纹不返回给玩家。
- NPC复核提供当前房源属性与尚未结束的相关会谈。模型可以保留顾虑，但不能把已知房源属性说成未安排的保障。
- 签约支付、分配、签署记录在同一事务内完成，付款日期取实际签署日。网络重试及过期版本不能重复扣除。
- 行政文件的审校流程独立，未因本次合同改动而取消。

## 回归覆盖

后端覆盖 `test_contract_workflow_v2.py`、原合同账务、事实与信息边界用例；网页覆盖合同弹窗、协商入口、只读正文、未保存修改保护与旧版本答复；终端客户端同步使用只读预览和直接复核流程。

无实物住房方案省略交房日；内部兼容值使用搬离日，不渲染成交房承诺。选择住房时仍须填写有效交房日。合同教程按填写、预览、反馈、签署和旧草案分别讲解，教程按钮不会提交业务。
