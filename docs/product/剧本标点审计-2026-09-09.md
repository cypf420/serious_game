# 剧本与旁白标点审计

日期：2026-09-09。

## 结论

截图中的异常由运行时文本处理产生，不是图片或字体编码损坏。已经修复两处后端处理问题，并补齐旧存档的前端显示兼容。

- 句子本身以 `。”`、`？」` 等形式结束时，后端不再在右引号外追加句号。
- 删除内部标记时，不再按每一个句号拆开再拼接；保留完整引语、问号、感叹号和段落边界，避免丢失右引号。
- 已经保存为 `。”。`、`。」。` 的旧文本，在显示时去掉多余句号；正常的短语引用（例如：这叫“先核实”。）仍保留引号外的句号。
- 沿用已有的引号统一处理，将「」显示为“”，嵌套引用显示为‘’。不改剧情字词、内容包哈希或玩家存档。

## 范围与方法

扫描当前工程中 249 个文件、37,232 条含中文的文本记录。范围包括：

- `最终剧本.md`、`docs/game_design` 下的文本资料。
- 三个内容包中的 JSON 与模型提示词，以及 authority、editorial 编辑源数据。
- 后端源代码、剧本构建与导出工具。
- 网页应用与终端前端的文本源文件。

JSON 按解码后的字符串检查，Python 按 AST 字符串检查，其他文本文件按行列出候选。代码片段、插值字符串与历史记录可能产生误报，不能将候选数量理解为确认错误数量。详细逐文件清单与候选位于 `E:/严肃游戏/output/punctuation-20260909/full-audit.json`，可用新增工具 `code/backend/tools/audit_story_punctuation.py` 重跑。

对正式包 `pkg_gameplay_v3` 另外使用现有字段白名单枚举全部 4,048 条登记的玩家可见文本，并逐条检查引号配对、错误嵌套、重复标点、替换字符、半角逗号/分号/冒号/问号/感叹号与单个省略号。剧情、决策、结局的正文同时经过真实后端旁白处理后再次检查。
