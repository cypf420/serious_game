# 结局展示与阅读分页

## 数据与结局规则

24 个主结局、95 个子结局使用同一个 `app/ending/EndingExperience.tsx`。前端只展示后端已选定的主文、子文和附记，不选择结局，不调用 AI 改写，不加载其他结局文案。

后端 `EndingService.project_result` 为新旧存档统一投影 `signed_households`、`total_households`、`target_signed_households`。实际户数取自已审计台账；状态栏、结局卡、复盘共用这一来源。没有可靠数据时前端显示“待核实”，不将缺失值作为 0。0 户是有效实绩。

达标目标为 30/36，原有 ≤27、28—29、30—31、32—33、34—36 档位及结局优先级保持不变。`_render_sub_text` 只替换已确认指向本局台账的旧文句式；不要全局替换 27、29 或 30，不要改写引用、历史事实或政策目标。新增结局句式时同时补充幂等测试和边界测试。

旧存档的结局与 `ending:final` 叙事通过只读投影补齐，不改写存档。已经在浏览器缓存的旧叙事需重开存档，从头拉取 feed 后更新。

## 展示与进度

桌面宽度 78vw，窄屏 96vw，最大高度 92dvh。主结局大号朱红标题，纸张底色。右上关闭、Escape、底部关闭均可退出；关闭后恢复原焦点，顶部“查看结局”可重开。

账号、存档、主结局 ID、子结局 ID 共同构成阅读身份。`serious-game:ending:v1:` 本地存储保存关闭状态和原文偏移；存储不可用时回退内存。关闭过的同一结局不再自动弹出。业务弹窗或处理中暂缓展示。必须核对可见状态的 session_id，避免加载失败后把旧结局显示为新存档结果。

正文顺序为主文、子文、附记；附记仅展示标题和正文，不暴露内部标识。参考图数据只用于浏览器测试，不写入游戏。

## 共享分页

`app/reading/pagination.ts` 保存原文字符偏移，优先按自然段分页，每页最多三段；段落过长时按完整句子拆分。`PagedReading.tsx` 根据实际字体、宽度和阅读区域高度测量，监听尺寸变化，重排后继续显示包含原偏移的位置。

遇到单个句子本身高于视口时保留整句，正文区域可滚动，避免截断或漏字。字号与视口变化不会改变源文本。结局翻页只更新本地阅读位置，绝不额外提交行动或决策。

按用户回退要求，分页仅用于结局弹窗与复盘结局。结局之前的剧情、会谈显示与剧情回看已恢复至 d9b3ccb 的实现，继续使用原有“上一段／下一段”导航，不接入新增分页器。
