## 一、AI 请求期间缺少明确反馈

### 问题

玩家点击“送出回应”、夜间结算、会议发言、合同转写或文书生成后，模型返回前界面看起来像卡住。原有局部小字不醒目，玩家难以判断点击是否成功，也可能重复提交。

### 优化方案

- 所有真实 AI 操作统一接入中央等待层。
- 请求发出后立即在工作区中央显示“AI 正在思考”。
- 根据任务显示“正在生成人物回应”“正在生成会议意见”“正在进行夜间结算”等具体说明。
- 主标题使用 22-24px 字号，深色高不透明背景保证对比度。
- 等待期间锁定重复提交控件，请求成功、失败或取消后自动移除。
- 增加 `role=status`、`aria-live`、`aria-busy` 和减少动画支持。

### 证据

下图为真实人物访谈请求发出后的即时状态。中央提示清晰可见，输入框和发送按钮已经锁定。

## 二、follow-up 会议与夜间场景文字可读性不足

### 问题

原 follow-up 班子会议沿用普通剧情背景，遮罩偏浅；立绘、背景细节和正文互相干扰。夜间会谈也缺少专用空间，玩家不容易区分普通剧情和强制会谈。

### 优化方案

- follow-up 和主动班子会议统一使用独立的县政府夜间会议室背景。
- 背景不包含人物和文字，中部保留正文阅读空间。
- 场景遮罩提高至约 62%，正文面板不透明度提高至约 94%。
- 夜间强制会谈使用独立舞台、独立标题和状态栏。
- 人物立绘与文字时间线分栏，避免立绘遮挡正文。
- 1920×1080、1366×768 和 390×844 均采用相应布局，页面无横向溢出。

### 证据

下图为 1366×768 下的夜间强制会谈。深色阅读层与右侧案头区分明确，立绘、发言记录和结束按钮互不遮挡。

![夜间强制会谈独立舞台](optimization-evidence/night-forced-conversation.png)

## 三、夜间强制会谈轮次化、无法回看且结束方式不清楚

### 问题

固定三轮会谈缺少真实博弈感；人物 A 回答后直接切换到人物 B，玩家来不及阅读，也不能稳定回看。玩家不知道怎样才能结束强制会谈，系统也可能仅因轮次耗尽而自动放行。

### 优化方案

- 删除固定轮数和“还需 X 轮”的完成语义。
- 每轮由真实 LLM 从 `press`、`challenge`、`soften`、`settle`、`reopen`、`close` 中选择人物行为，再生成自然语言。
- NPC 是否停止追问取决于人物性格、长期记忆、当前信任、核心担忧、玩家说法及现场矛盾。
- 玩家可以给出可信方案、画饼、回避或欺骗，但“NPC 暂时相信”不等于客观承诺已经兑现。
- 已 `settle` 的人物继续留在现场；新矛盾出现时可以 `reopen`。
- 全部参与者暂时接受后，前端提示“等待发起人确认收束”。
- 只有发起人选择 `close` 后，才显示“结束夜间会谈”。玩家点击后归档完整记录并恢复次晨流程。
- 时间线永久保留本场全部发言；点击历史发言可以重新查看对应人物立绘。
- 玩家停留在历史位置时不强制跳到底部，而是显示“有新发言”。

### 证据

上图的完整时间线同时保留玩家、孙强和赵建国的发言。孙强显示“暂时接受”，赵建国最终显示“确认收束”；页面底部此时才出现“结束夜间会谈”。画面还明确提示：停止追问不代表承诺已经兑现。

真实 API 结果也证明会谈不是统一自动放行：

| 场景 | 发起人物 | 真实模型结果 |
|---|---|---|
| D10 县镇汇报 | 赵建国 | `settle`，接受真实进度和责任清单方案 |
| D29 材料保护 | 赵建国 | `press`，继续追问由谁保护、程序如何背书 |
| D40 迁坟安置 | 吴秀英 | `settle`，要求逐户听取散姓住户意见 |
| D55 环境治疗 | 石文斌 | `settle`，继续强调原件交接和独立复核 |
| D70 公开监督 | 陈默 | `settle`，明确暂时停止追问不等于认可已兑现 |
| D84 终局整改 | 张立 | `settle`，要求责任人、证据和期限逐项复核 |

## 四、多人台词重复以及模型纠错方向错误

### 问题

多人会谈中，不同 NPC 可能生成完全相同的句子。旧校验将“重复他人台词”误判为“包含未授权事实”，导致真实模型收到错误纠错提示，连续重试后仍可能失败。

### 优化方案

- 将“未授权事实”和“重复他人台词”拆分为两套独立安全校验。
- 表达阶段注入当前人物的核心担忧和说话方式。
- 将本场已有 NPC 发言作为独立的 `forbidden_repeat_signatures`。
- 命中重复时明确要求“不要重复其他在场人物已经说过的句子，只回应当前角色最关心的不同要点”。
- 纠错只重新生成表达，不重新抽取更有利的业务选择。
- 重试、断流、旧 worker 返回和 ABA 场景均不得产生部分提交。

### 证据

夜间会谈截图中的最新一轮中，孙强从基层执行角度要求“责任人和期限落到纸面”，赵建国从县级责任角度确认收束并表示继续盯进度；两人的新发言不再完全相同。

## 五、人物卡指标与说明重复，人物出现条件不准确

### 问题

人物卡上方已经有“信任、态度、焦虑”三个标签，下方又出现大字号重复解释，信息冗余且可能与指标不同步。另外，仅被卷宗提到的人物曾被误写成“剧情已经介绍、可以继续沟通”，容易让玩家误以为已经见过本人。

### 优化方案

- 人物列表只保留姓名、身份、联系状态和三个小型关系标签。
- 删除指标下方的大字号重复说明。
- 指标和“最近关系变化”由同一后端关系事件投影生成，禁止前端自行拼接另一套结论。
- 区分“卷宗提及”和“本人已正式进入剧情”。
- 何铁柱、刘三、周大山等尚未正式接触的人物显示“卷宗提及 · 尚未接触”，不开放会谈入口。
- 人物正式进入治理现场后才允许显示可联系机会。

### 证据

下图右侧人物列表中，何铁柱和刘三显示“卷宗提及 · 尚未接触”；已见面的孙强、赵建国只显示紧凑的关系标签，没有下方重复大字。

## 六、“已揭示关系”混入待核实文案

### 问题

“已揭示关系”中曾出现“已记录待核实”“尚待观察”等开发态占位文案，玩家无法判断关系到底是否已经确认。

### 优化方案

- “已揭示关系”只展示后端标记为 `confirmed` 的关系。
- `suspected` 关系进入线索区域，不再伪装成已经揭示。
- 删除“已记录待核实”“待核实”“尚待观察”等关系原因占位句。
- 原因为空时不显示替代套话。

### 证据

人物卡截图中，未正式接触者只显示其公开来源和接触状态；已经见面的人物只显示当前关系指标，不再附加“已记录待核实”等大段占位说明。

![确认关系与人物状态](optimization-evidence/people-cards-compact.png)

## 七、线索、档案和决策之间缺少明确关系

### 问题

玩家取得线索后不知道它能做什么；证据型决策也没有清楚说明缺少哪项材料，查档和会谈因此容易沦为与决策无关的附加操作。

### 优化方案

- 线索卡显示来源、证据等级和具体用途。
- 决策选项增加“已掌握”“尚缺”和玩家安全的取得方式。
- 缺少事实的证据型选项继续显示但禁用，提供前往线索或查档页的入口。
- 查档和人物会谈取得同一事实时均可解锁相应决策，但只有已读档案能作为会议和正式文书依据。
- 每个决策保留至少一个不依赖证据的合法方案，忽略调查仍可推进至 D90。
- AI 会谈只能引用当前已经掌握并允许披露的事实。

### 证据

下图的“两百万前期协调费”线索同时显示来源和用途，明确提示可追问经手人、审批链、收款方与实际用途，并提醒“金额异常本身不等于已经定罪”。

![线索来源与具体用途](optimization-evidence/clues-strategic-uses.png)

## 八、决策可能早于剧情铺垫出现

### 问题

存档恢复、阅读游标或 `pending_decision` 状态处理不一致时，前端可能先显示选择题，再显示解释该选择的剧情铺垫，造成“决策比剧情先出现”。

### 优化方案

- 使用稳定的 `presentation_entry_id` 作为唯一展示门槛。
- 剧情铺垫段必须先于决策展示段。
- 阅读游标不能跳过当前铺垫。
- 保存载入后恢复到最早未读内容，不因已经存在 `pending_decision` 就提前显示选项。
- 内容加载时拒绝缺少铺垫、绑定错误或顺序倒置的决策。
- 对 D1-D90 验证“剧情铺垫 → 决策提示 → 选项开放”的顺序。

### 证据

本次回归中，新游戏 D1 必须先依次读完 39/39 个剧情段落，选择项才开放；保存载入测试同时验证恢复后仍停在最早未读内容。该项主要由顺序状态测试证明，线索截图也展示了当前剧情仍停留在“今日 41/41”，右侧线索仅作为辅助材料展示，没有提前覆盖主剧情决策。

![剧情阅读与线索区域相互独立](optimization-evidence/clues-strategic-uses.png)

## 九、真实 API 能力与运行可靠性

### 问题

如果模型不支持稳定的结构化输出，夜间会谈、合同或文书可能在运行中失败；过去依赖 Fake 或模板降级会掩盖真实玩家体验。

### 优化方案

- API 启用前测试单选、多选、人物表达、夜间与后续会谈、合同转写和行政文书转写六项能力。
- 业务结构统一采用“引擎给候选 → AI 选择 → AI 表达”。
- 模型不能自由拼装人物、行动、合同金额或权威状态。
- 无效输出只允许同一真实模型最多两次定向纠错。
- 纠错失败时保持游戏状态不变，不回退 Fake 或模板台词。
- API Key 仅存在后端登录会话内存，不写入存档、日志、审计正文或浏览器存储。

### 证据

下图显示服务器默认 `qwen3.6-plus` 已启用，六项游戏能力已经验证。API Key 以密码形式遮蔽。

![AI 接口六项能力已验证](optimization-evidence/ai-api-capabilities-verified.png)

真实验收会话产生 18 条模型审计记录，Fake 记录为 0。

## 十、合同入口脱离会谈，玩家可以在治理页随时办理

### 问题

合同提议原本由人物会谈触发，但前端会从全部未完成合同中全局选择一份，因此玩家进入其他治理行动时仍可能看到“签订合同”。治理页又长期展示全部未完成合同的办理入口，形成“任何时间、对任何家庭都能继续签约”的错觉。仅依靠前端隐藏也不足以保证规则成立，玩家或旧页面仍可能直接调用合同确认、改条款、送审和签署接口。

### 优化方案

- 合同意向只在 `household_visit` 入户会谈的真实对话中识别，不在治理页提供全局发起入口。
- 批次确认必须存在与该批次代表匹配的进行中入户会谈。
- 合同条款核定、正文修改、送审和正式签署，必须存在与该批次代表或本户直接签约人匹配的进行中入户会谈。
- 前端只在当前会谈对象与合同代表或直接签约人匹配时展示未完成合同工作区。
- 治理页改为“逐户合同记录”：已签合同可以查看，未完成合同只提示玩家返回相关人员或代表的入户会谈继续办理。
- 伪造合同 ID、在错误人物会谈中办理或没有会谈时直接调用接口均被后端拒绝；状态版本、合同、资源占用和快照保持不变。
- 不自动提供“保证通过”的合同基准方案，合同条款仍由玩家自主探索；本次只修正合同入口和权限边界。

### 证据

下图为真实游戏中的吴秀英入户会谈。右侧仍明确显示“完成正在进行的入户走访”，合同核定工作区只在这场匹配会谈中打开，而不是从治理页常驻进入。

![合同仅在相关人员入户会谈中办理](optimization-evidence/contract-in-household-conversation.png)

自动化回归进一步验证截图无法证明的负向边界：

- Backend `test_contract_batch_confirmation_requires_the_matching_live_conversation`：没有会谈或会谈对象不匹配时拒绝确认合同批次。
- Backend 合同全流程回归：条款核定、修改、送审、签署均经过代表或直接签约人会谈校验。
- Web `shows unfinished contract work only during the matching representative conversation`：其他行动不显示合同入口，并覆盖直接签约人继续办理本户合同。

## 十一、强制会谈关系、记忆事务与前端状态存在不一致

### 问题

本轮复检还发现以下相互关联的问题：强制会谈没有把人物当前的“信任、态度、焦虑”传给真实模型；NPC 已经作出的成功回应可能因后续流式传输失败而被错误撤销记忆；普通治理会谈曾先提交游戏状态、后写人物记忆，记忆失败时会形成半提交；`press`、`reopen` 等继续追问动作没有保存玩家当轮承诺；NPC 私密的说服判断规则进入了自然语言表达提示词；前端 AI 配置模式与服务端状态可能不同步；新发言写入 DOM 后才判断滚动位置，导致玩家回看历史时仍可能被拉到底部。

### 优化方案

- 强制会谈每轮冻结并传入当前人物关系投影，包括信任、态度和焦虑，模型不再只看到静态角色设定。
- 私密说服规则只进入低温度选择阶段；表达阶段仅接收已确认选择、允许事实、人物设定和公开上下文，避免人物机械复述隐藏判断标准。
- 只要玩家当轮说法非空，无论 NPC 选择追问、质疑、动摇还是暂时接受，都生成对应人物记忆候选。
- 人物记忆写入、精力扣除、权威会谈记录、状态版本和快照使用同一提交边界；记忆写入失败时整体回滚。
- 游戏状态已经成功提交后，即使浏览器断流或确认送达失败，也不再删除已经提交的人物记忆。
- API 配置面板以 `GET /api/ai/config` 的权威模式恢复界面，不再默认显示错误选项。
- 夜间时间线在新内容写入前记录玩家是否位于底部；玩家正在回看历史时只显示“有新发言”，不强制滚动。

### 证据

夜间会谈截图中的完整时间线仍是本项前端证据：人物状态、历史发言和收束结果同时保留，玩家可以停留回看。

![强制会谈人物状态与完整时间线](optimization-evidence/night-forced-conversation.png)

对应自动化证据包括：

- `test_group_persuasion_receives_current_relationship_state`：信任、态度、焦虑进入强制会谈判断上下文。
- `test_committed_group_memory_survives_stream_delivery_failure`：提交后的记忆不因流式送达失败而丢失。
- `test_governance_turn_does_not_commit_when_memory_persistence_fails`：记忆写入失败时治理会谈无部分提交。
- 表达隔离测试：私密判断规则存在于选择请求，但不出现在最终表达请求。
- Web 回归：API 模式以服务端状态恢复；时间线使用更新前滚动状态决定是否跟随新发言。
